# هوشیار POS — سامانه فروش و مدیریت رستوران (نسخه ۲)

نسخه ۲ هوشیار یک سامانه آفلاین‌محور برای ثبت سفارش رستوران، مدیریت میز، تسویه، صدور و بایگانی فاکتور، گزارش‌گیری و اتصال به چاپگرهای حرارتی است. رابط کاربری در وب‌اپ پیاده‌سازی شده و همان فایل‌ها در Android WebView همراه با پل بومی چاپ، پیام‌رسانی و کارتخوان اجرا می‌شوند.

## دریافت و نصب Android

آخرین APK آزمایشی از فایل `HooshyarPOS-debug.apk` در ریشه مخزن قابل دریافت است. نسخه Debug برای نصب مستقیم و ارزیابی است، نه انتشار عمومی فروشگاه. در Android نصب برنامه از منبع مورد اعتماد را فعال کنید و فایل APK را باز نمایید. نسخه‌های تازه پس از موفقیت GitHub Actions در همین مسیر قرار می‌گیرند.

## راه‌اندازی محیط پیش‌نمایش

نیازمند Node.js نسخه ۱۸ یا جدیدتر؛ وابستگی npm خارجی ندارد.

```bash
npm test       # آزمون‌های منطق و قراردادهای نسخه ۲
npm start      # پیش‌نمایش وب روی http://localhost:3000
```

برای آزمون روی LAN، `HOST=0.0.0.0 PORT=3000 npm start` اجرا کنید. مرورگر باید از دستگاهی باز شود که به همان شبکه چاپگر شبکه‌ای دسترسی دارد. پل چاپ شبکه وب از `POST /api/print` استفاده می‌کند؛ USB، Bluetooth، پیامک/اشتراک‌گذاری اندروید و اجرای PSP به برنامه Android نیاز دارند.

## ورود آزمایشی

| کاربر | رمز | سطح |
|---|---:|---|
| `admin` | `1234` | مدیر کل |
| `cashier` | `2222` | صندوقدار |
| `waiter` | `3333` | سفارشگیر |
| `kitchen` | `4444` | آشپزخانه |

این گذرواژه‌ها صرفاً برای نصب تازه و ارزیابی هستند. قبل از استفاده عملی، رمزها را تغییر دهید، کاربران/مجوزها را بازبینی کنید و نسخه پشتیبان امن بگیرید. ورود دو مرحله‌ای ابتدا کاربر و سپس گذرواژه را انتخاب می‌کند.

## کنسول فروش

صفحه فروش ابتدا سالن‌ها و میزها را نمایش می‌دهد؛ تا وقتی میز انتخاب نشده باشد، فهرست کالاها و غذاها پنهان است. پس از انتخاب میز، گروه‌ها و کالاها برای افزودن به سفارش ظاهر می‌شوند. برای سفارش بیرون‌بر نیز با ایجاد سفارش، منو در دسترس قرار می‌گیرد. سپس می‌توان مشتری و سفارش‌گیر را تعیین کرد، تخفیف و یادداشت ثبت کرد، پرداخت ترکیبی انجام داد، میز را جابه‌جا کرد و فاکتور/چاپ را مدیریت کرد. عملیات‌ها از هم جدا هستند:

- «ذخیره» فقط پیش‌نویس را نگه می‌دارد و چاپ نمی‌کند.
- «چاپ سفارش» رسید مشتری/آشپزخانه را بدون تسویه ارسال می‌کند.
- «ثبت سفارش» سفارش را قطعی و اقلام را به ایستگاه‌های چاپ می‌فرستد؛ میز اشغال می‌ماند.
- «ثبت و چاپ نهایی» ابتدا روش پرداخت را می‌پرسد، پرداخت را اعتبارسنجی می‌کند، فاکتور نهایی را می‌سازد، چاپ می‌کند و فقط در موفقیت تسویه میز را آزاد می‌کند.

## اطلاعات و پشتیبان‌گیری

«اطلاعات پایه» از زیرمنوی کناری باز می‌شود و شامل کالا/موجودی، گروه‌ها، سالن و میزها، چاپگرها و ایستگاه‌ها، کاربران و سطوح دسترسی، پرسنل و پورسانت، مشتریان، روش‌های پرداخت و PSP است. برای مدیریت میز و سالن در همان صفحه، ابتدا سالن را بسازید و سپس کارت آن را انتخاب کنید تا فهرست میزهای همان سالن نمایش داده شود. تعداد واردشده «تعداد میز جدید برای افزودن» است و شماره‌گذاری از آخرین میز ادامه می‌یابد؛ مثلاً با افزودن ۱۰ میز به میزهای ۱ تا ۱۰، میزهای ۱۱ تا ۲۰ ساخته می‌شوند. ویرایش نام/ظرفیت میز و ویرایش نام/رنگ سالن نیز از همین صفحه در دسترس است. گزارش‌های عملیاتی و ممیزی در داده محلی ثبت می‌شوند. تنظیمات مالی، سیاست کسر موجودی و باشگاه مشتریان در «تنظیمات سامانه» قرار دارد.

داده‌ها به‌صورت محلی در مرورگر با کلید نسخه‌دار `hooshyar.pos.data.v2` ذخیره می‌شوند؛ برنامه Android یک نسخه پشتیبان بومی نیز نگه می‌دارد. از صفحه تنظیمات نسخه JSON را به‌طور منظم دریافت و خارج از دستگاه امن نگهداری کنید. بازیابی یک نسخه، داده‌های موجود را جایگزین می‌کند.

## فاکتور مشتری و محدودیت‌ها

لینک فاکتور مستقلِ صفحه `webapp/invoice.html` برای مشاهده/چاپ آفلاین اطلاعات فاکتور را در پیوند کدگذاری می‌کند. این پیوند یک snapshot فقط‌خواندنی و حامل‌محور است: اطلاعات در URL کدگذاری شده‌اند، نه رمزنگاری؛ هر دارندهٔ پیوند می‌تواند آن را بخواند و لغو دسترسی پس از ارسال وجود ندارد. برای ارسال عملی، نشانی عمومی قابل‌دسترسی را در `linkBase` تنظیم کنید و `webapp/invoice.html` را همان‌جا میزبانی کنید. APK خام به‌تنهایی نشانی عمومی ندارد. برای داده‌های حساس از سرویس سمت‌سرور با دسترسی قابل‌لغو استفاده کنید. ارسال پیام در Android صفحه تأیید پیامک/اشتراک‌گذاری سیستم را باز می‌کند و پیام را بی‌اجازه ارسال نمی‌کند.

اتصال PSP وابسته به اپلیکیشن، قرارداد و قالب Intent دستگاه واقعی است. پیکربندی‌های اولیه صرفاً نمونه‌اند؛ قبل از تراکنش واقعی باید روی کارتخوان و اپ PSP مورد استفاده اعتبارسنجی شوند. چاپگر USB/Bluetooth و برش/کشوی پول نیز به مدل سخت‌افزاری واقعی نیاز به آزمون میدانی دارد.

## ساخت APK از سورس

GitHub Actions پس از push، `npm test` را اجرا و سپس با Java 17 و Gradle 8.7 APK Debug را می‌سازد. Web assets در زمان ساخت از `webapp/` به assets برنامه همگام می‌شوند. APK موفق به‌عنوان artifact منتشر و در ریشه مخزن جایگزین می‌شود.

```bash
cd android
gradle :app:assembleDebug
```

ساخت محلی به Android SDK، JDK 17 و Gradle 8.7 نیاز دارد. مخزن شامل امضای انتشار نیست؛ خروجی Debug را برای انتشار تجاری به‌کار نبرید.
